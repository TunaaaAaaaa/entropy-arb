## EXP-001：我在决策时真的知道这条信息吗
关联：CASE-002 的事件时间；CASE-001 的状态新鲜度。全部输入为人工构造，与真实人物交易无关。
命题：按事件发布时间回放、或把最后收到的消息当成最新状态，可能得到当时无法获得或已经过时的信息。
## 先预测，再运行
输入 events.json 含三个同一数据源的报价事件：A 在 00 秒产生、01 秒收到；B 在 02 秒产生、07 秒收到；C 在 04 秒产生、05 秒收到。
在 04.5 秒决策时，哪些事件真的已经收到？在 07.5 秒，最后到达的 B 是否比已收到的 C 更新？写下答案再运行：
```powershell
python research-workbench/experiments/001-evidence-timing/replay.py
```
## 验收
第一次决策只能知道 A；按发布时间回放却会错误使用尚未收到的 C。第二次决策已经知道 C，迟到的 B 不应把状态倒退。
脚本包含这些判据的断言，并生成 result.json，记录输入哈希、Python 版本、运行时间和结果。固定输入的决策结果应可重复，运行时间可以变化。
本样例假定事件源和本机时钟可比较、三个事件来自同一可排序的数据源。真实平台应依据其正式序列号/快照与增量协议处理顺序；仅比较时间戳不足以保证订单簿完整性。
下一步：增加重复、同时间不同序号、断线期间缺失的事件，先写预期结果，再扩展验证规则。这里验证的是数据处理方法，不是收益或实际成交。
